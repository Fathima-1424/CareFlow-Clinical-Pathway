    "# CareFlow: Clinical Pathway Process Mining\n",
    "\n",
    "### 1. Project Overview\n",
    "\n",
    "CareFlow is a healthcare operations and process-mining project that analyzes patient journeys through a simulated hospital emergency-care pathway.\n",
    "\n",
    "The project uses timestamped patient event data to understand the actual sequence of hospital activities and compare it with a proposed ideal reference pathway.\n",
    "\n",
    "The purpose of conformance checking is to identify differences between observed patient journeys and the reference process model.\n",
    "\n",
    "### 2. Project Objectives\n",
    "\n",
    "- Prepare and analyze patient event logs.\n",
    "- Discover actual patient pathways using PM4Py.\n",
    "- Define a proposed ideal hospital pathway.\n",
    "- Compare actual patient journeys with the reference process model.\n",
    "- Identify frequent process deviations.\n",
    "- Provide operational recommendations based on the analysis.\n",
    "\n",
    "### 3. Tools and Technologies\n",
    "\n",
    "| Tool | Purpose |\n",
    "|---|---|\n",
    "| Google BigQuery | Store and query patient event data |\n",
    "| dbt | Transform and standardize event records |\n",
    "| Python | Data preparation and analysis |\n",
    "| PM4Py | Process discovery and conformance checking |\n",
    "| Jupyter Notebook | Execute and document analysis |\n",
    "\n",
    "### 4. Dataset Description\n",
    "\n",
    "The dataset contains 5,000 patient cases and approximately 28,000 recorded events.\n",
    "\n",
    "The main event-log attributes used for process mining are:\n",
    "\n",
    "- Case ID — identifies a patient visit.\n",
    "- Activity — identifies the recorded hospital activity.\n",
    "- Timestamp — records when the activity occurred.\n",
    "\n",
    "### 5. Proposed Ideal Reference Pathway\n",
    "\n",
    "The project uses the following simplified reference pathway:\n",
    "\n",
    "1. Registration\n",
    "2. Triage\n",
    "3. Optional investigation activities, such as Lab Test, X-Ray, and Imaging\n",
    "4. Treatment\n",
    "5. Doctor Consultation\n",
    "6. Final outcome: Discharge or Admission\n",
    "\n",
    "This is a proposed analytical reference model. It must be validated against an approved hospital protocol before deviations can be interpreted as clinical non-compliance.\n",
    "\n",
    "### 6. Conformance Checking Methodology\n",
    "\n",
    "The actual patient event log was converted into a PM4Py event log.\n",
    "\n",
    "The proposed reference process was represented as a Petri net.\n",
    "\n",
    "PM4Py alignment-based conformance checking was used to compare actual patient journeys with the reference model.\n",
    "\n",
    "The analysis also used token-based replay fitness as a second conformance measurement.\n",
    "\n",
    "Alignment moves were examined to identify:\n",
    "- Activities recorded in the actual log but not matched by the model.\n",
    "- Visible activities expected by the model but missing from the actual journey.\n",
    "\n",
    "Silent model transitions were excluded from the visible missing-activity count.\n",
    "\n",
    "### 7. Conformance Checking Results\n",
    "\n",
    "The analysis covered 5,000 patient cases.\n",
    "\n",
    "| Metric | Result |\n",
    "|---|---:|\n",
    "| Total patient cases | 5,000 |\n",
    "| Cases with detected deviations | 3,956 |\n",
    "| Cases without detected deviations | 1,044 |\n",
    "| Deviation rate | 79.12% |\n",
    "| Completely fitting traces | 20.88% |\n",
    "| Alignment average fitness | 0.8849 |\n",
    "| Alignment log fitness | 0.8809 |\n",
    "| Token-based average trace fitness | 0.8532 |\n",
    "| Token-based log fitness | 0.8632 |\n",
    "\n",
    "The results indicate that 1,044 patient journeys fit the current reference model without detected deviations. The remaining 3,956 journeys contained at least one detected alignment deviation.\n",
    "\n",
    "The average alignment fitness was approximately 0.8849. This indicates a relatively high degree of alignment similarity even though many individual traces contained deviations.\n",
    "\n",
    "### 8. Major Deviation Patterns\n",
    "\n",
    "The deviation analysis identified recurring patterns, including:\n",
    "\n",
    "- Missing Treatment activity.\n",
    "- Return to Triage appearing in actual patient journeys.\n",
    "- Additional Triage and X-Ray activities.\n",
    "- Combinations of extra actual activities and missing reference activities.\n",
    "\n",
    "The missing Treatment pattern was especially frequent in the current analysis.\n",
    "\n",
    "These patterns indicate that the proposed reference model may not represent every pathway present in the event data.\n",
    "\n",
    "### 9. Key Findings\n",
    "\n",
    "1. Not all recorded patient journeys follow the proposed reference sequence.\n",
    "2. Return to Triage is an important pathway pattern that requires further investigation.\n",
    "3. The Treatment requirement in the reference model has a substantial effect on the deviation results.\n",
    "4. A high number of detected deviations does not necessarily indicate clinical errors.\n",
    "5. The reference model should be reviewed and validated before operational conclusions are drawn.\n",
    "\n",
    "### 10. Recommendations\n",
    "\n",
    "- Validate the proposed ideal pathway with a qualified hospital representative or mentor.\n",
    "- Review whether Treatment is mandatory for every patient journey.\n",
    "- Investigate the operational reason for Return to Triage events.\n",
    "- Consider approved re-triage loops in a revised reference model if the clinical protocol permits them.\n",
    "- Review the most frequent deviation patterns with operational stakeholders.\n",
    "- Use validated process rules when producing final compliance measurements.\n",
    "\n",
    "### 11. Limitations\n",
    "\n",
    "- The dataset is simulated and should not be treated as evidence of actual hospital performance.\n",
    "- The reference pathway is a project assumption rather than a verified hospital policy.\n",
    "- The simplified reference model may not represent every legitimate patient pathway.\n",
    "- Alignment deviations do not independently establish clinical non-compliance or patient-safety issues.\n",
    "- Event timestamps do not necessarily represent pure waiting time.\n",
    "- Further validation is required before making operational or clinical claims.\n",
    "\n",
    "### 12. Conclusion\n",
    "\n",
    "The CareFlow conformance analysis compared 5,000 simulated patient journeys with a proposed reference process model using PM4Py.\n",
    "\n",
    "The analysis identified a deviation rate of 79.12%, an alignment average fitness of approximately 0.8849, and recurring differences involving missing Treatment and Return to Triage activities.\n",
    "\n",
    "The results demonstrate how process mining can be used to identify differences between actual event sequences and a reference pathway. Before the findings are used for operational decisions, the reference model and detected deviations should be validated against approved hospital procedures.\n",
    "\n",
    "### 13. Project Deliverables\n",

    "- Actual patient journey analysis.\n",
    "- PM4Py process discovery and reference Petri-net models.\n",
    "- Patient-level conformance deviation results.\n",
    "- Deviation summary CSV.\n",
    "- Conformance checking notebook.\n",
    "- Final CareFlow conformance report.\n"
